# CSV and TSV interpretation

P02 separates bounded byte reading, strict decoding, syntactic records, and header interpretation. The native decoder reads in configurable chunks up to a 64 MiB input limit, then decodes the bounded byte sequence once. A leading BOM selects UTF-8, UTF-16 LE/BE, or UTF-32 LE/BE before automatic UTF-8. Explicit Windows-1252 and ISO-8859-1 choices are separate; invalid UTF-8 and malformed UTF-16/32 fail with a stable `invalidEncoding` diagnostic. Only a byte-zero BOM is removed. The full bounded byte sequence is accumulated before decoding; P06 must measure and reduce peak memory for large batches.

The scalar parser keeps CR, LF, and CRLF record boundaries distinct across chunks, retains their exact bytes as decoded text inside quoted fields, and preserves spaces, empty records, trailing empty fields, and literal CSV strings. An unclosed quote, a quote inside an unquoted field, or text after a closing quote is `malformedDelimitedText` with record/field/line information. A malformed file publishes no normal artifact, while the batch continues. No silent recovery mode is enabled.

The app exposes encoding, header, comma/tab/semicolon or one-scalar custom delimiter, and explicit `sep=` preamble options. Automatic header mode keeps the first syntactic record as data and records `headerUnconfirmed`. Automatic delimiter mode checks consistent multi-column samples; an ambiguous sample falls back to comma with `delimiterUnconfirmed`. TSV suggests tab. The applied encoding/provenance, delimiter, header mode/confirmation, and interpretation warnings appear in CSV/TSV JSON `source.importSettings`, in Markdown, and in the per-file conversion report. Empty input receives an `empty` report status rather than `converted`.

CSV/TSV JSON schema version changed from `1.1` to `1.2` for the additive `source.importSettings` object. Existing non-delimited outputs remain `1.1`. A consumer can ignore the new optional object if it does not need import settings; consumers that branch on the schema version should accept `1.2` for CSV/TSV. Automatic header behavior changed: a first record previously guessed as a header may now appear as data until the user explicitly selects header-present. To retain old behavior for a known headered file, select header-present. The two committed CSV fixtures explicitly contain headers and their expected cell/data values were reviewed unchanged before adding the new metadata.

P02 proves syntax and interpretation decisions, including the independent 34-case byte corpus and 1,000 seeded round trips. The current `content.data` projection can still lose duplicate headers and ragged cells; P03 will derive Markdown and JSON from one canonical ordered table model and version any incompatible schema changes. P02 success is not a claim of complete end-to-end table integrity.
