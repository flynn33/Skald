# Source intake and run lifecycle

The source picker accepts multiple individual files or folders. Dropping files/folders on the source row uses the same selection list. The target picker remains directory-only. The UI snapshots output format, CSV/TSV settings, recursion, and hidden inclusion at run start. It shows progress, permits cancellation, and allows a second start only after the prior task finishes. `ConversionManager` also rejects a concurrent start under its own run lock, independent of button state.

`SourceWorklistBuilder` snapshots source identities before the first output is published. It accepts direct files and enumerates selected directories, descending into nested directories only when the recursive option is on. It excludes a target subtree nested in an input directory; when source equals target, it keeps all original snapshot inputs and cannot ingest outputs created during that run. File identity (device and inode) deduplicates overlapping selections and hardlink aliases. Directory symlinks are never followed; explicit symlinks receive a diagnostic. FIFO/device/socket inputs are rejected before any read. RTFD directories are classified as document packages before generic directory handling; app bundles are not traversed as collections. Explicit hidden selections are honored, supported dotfiles such as `.env` remain discoverable, and other hidden discoveries obey the hidden toggle.

Known content signatures are checked against extensions before conversion. Unknown or extensionless regular files receive a bounded strict UTF-8 probe; confirmed text uses the normal text converter, while binary input is skipped with a reason. A `.csv` containing PDF bytes, for example, receives `extensionContentMismatch` instead of an attempted delimited conversion. CSV/TSV BOM or explicit legacy encoding still reaches the strict decoder. The probe is a dispatch check, not a substitute for each converter's full parser validation.

Each selected URL and the target URL attempts security-scoped access for the entire background run. Every successful start has one stop after work and cleanup. A false start is followed by actual filesystem access, so an already-accessible URL is not misreported as denied. The run does not persist bookmarks. Per-file read/probe/convert failures are reported without ending the batch. Cancellation stops new items and prevents publication before commit where the writer observes it; a committed prior output remains. Report counts state how many inputs were planned and how many reached terminal entries. The default worklist limit is 10,000 entries and maximum traversal depth is 32; exceeding either returns a controlled error rather than truncating the list. P06 will measure sustained-batch memory and cancellation latency across extraction stages.

Native P04 tests cover direct/multiple selections, nested target and recursion, `.env` and explicit hidden files, RTFD, app bundles, extensionless/unknown text, binary and conflicting signatures, duplicate hardlinks, symlink escape and loop cases, FIFO rejection, unreadable source, source-equals-target, BOM CSV, service-level concurrent-start rejection, cancellation, and restart. P08 observed native multi-file picker, signed sandbox access, and responsive cancellation/restart. The compiled production drop path passed its native test. The separate Xcode interaction test dragged two selected files from Finder into Skald and verified the Sources view reported `2 selected`.
