# Named format readers and boundaries

P07 adds compiled native readers for XLSX, BIFF8 XLS, ODS, and ZIP collections. The application remains version **1.0.0**, Xcode build **1**. Workbook and collection JSON use document schema **2.0**, which is a separate output contract. The fixture generator in `scripts/generate_format_fixtures.py` creates deterministic format files only for tests; production conversion does not call Python, a shell, an office application, or a document macro.

## Format and SDK decision

Apple's installed macOS 26.5 SDK exposes zlib as a module with `link "z"`. zlib decodes the raw DEFLATE stream and checks CRC32; it does not interpret ZIP headers. `SafeZipArchive` therefore validates ZIP32 end records, the central directory, local headers, member metadata, and checksums itself before handing a member to a format reader. Stored and raw-deflated members are supported. This bounded ZIP32 subset rejects ZIP64, multi-disk, encrypted, unsupported compression/flags, non-UTF-8 names, links/special entries, unsafe or colliding paths, declared/actual size disagreements, and expansion ratios above 100. The ZIP collection converter maintains a depth/entry/expanded-byte budget across nested archives, uses an owned 0700 temporary directory for member routing, and publishes one aggregate report through the production writer after all archive validation/conversion finishes. Unknown binary members remain visible as skipped; individual conversion failures make the collection partial.

XLSX uses the [SpreadsheetML package relationship model](https://learn.microsoft.com/en-us/office/open-xml/spreadsheet/structure-of-a-spreadsheetml-document) and a bounded offline `XMLParser` tree. It supports the Transitional spreadsheet namespace, root/workbook/worksheet relationships, shared and inline strings, numeric source lexemes, booleans, error values, formulas as expressions, unverified cached values, sparse explicit cells, built-in and recognized custom date styles, 1900/1904 epochs, and merged ranges. External relationships, DTD/entities, missing package parts, and unsupported cell types fail. Shared formula references without their own expression are warned as unresolved; formula caches are never recalculated or called fresh. Workbook formulas, links, scripts, and embedded macros are never executed. Unsupported package variants do not receive a general XLSX fidelity claim.

ODS follows the [ODF 1.3 package model](https://docs.oasis-open.org/office/OpenDocument/v1.3/OpenDocument-v1.3-part2-packages.html): spreadsheet MIME entry, manifest, and `content.xml`. It preserves table order/names, row/column repetitions under configured limits, covered/merged cells, text, numeric attribute lexemes, booleans, date/time values and null-date epoch, formula text and unverified cached values. Timezone is explicitly `floating` where the workbook provides none. Encrypted manifest entries and XML entities fail. ODS rendering/layout, external data sources, and formula evaluation are outside this reader's contract.

XLS is a real [MS-CFB](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-cfb/50708a61-81d9-49c8-ab9c-43c98a795242) compound file with a `Workbook`/`Book` stream, parsed as a [BIFF8](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-xls/f67ac5ed-b0a7-4b2c-9b7a-28933eeaac7e) subset. The bounded CFB reader validates v3/v4 allocation tables, sector chains, directory entries, and regular/mini workbook streams; it does not treat an extension-renamed text file as XLS. The BIFF8 reader handles worksheet order and names (`BoundSheet8`), simple non-rich/non-split SST strings, `LabelSst`, `Number`, `RK`, `MulRK`, `BoolErr`, `Blank`, numeric `Formula` cache, a small arithmetic/ref token subset, `XF` built-in date formats, `Date1904`, and `MergeCells`. Formula token bytes are retained as hex with an unsupported-token warning when expression reconstruction is incomplete; cached numbers are labelled unverified. BIFF4/older, password-protected `FilePass`, chart/macro/dialog sheets, rich/split strings, direct/unsupported cell records, and universal XLS layout/formula features are outside this tested subset. XLS binary numeric values are emitted with a round-trip 17-digit Double representation; unlike XLSX/ODS XML attribute lexemes, the binary input has no original decimal lexeme to preserve.

## Resource, provenance, and test boundary

Configured defaults: 64 MiB named-document input and member bytes, 1,000 archive entries, 256 MiB expanded archive bytes, nested depth 2, 128 sheets, 100,000 rows, 1,024 columns, and 250,000 populated cells across a workbook. Container XML also obeys the 16 MiB part, 100,000 node, and depth-64 ceilings. Exceeded limits fail with codes rather than truncation. ZIP output records archive/member path and depth separately from the flat safe temporary filename. Workbook output records ordered `sheets[]`, ordered sparse `cells[]`, type/text/numeric/formula/cache/date fields, merged ranges, and warnings. Markdown includes an inert recoverable JSON block per sheet; numeric and formula strings are data.

The committed deterministic fixtures include valid stored/deflated ZIP, nested/unknown members, a ZIP containing three named workbooks, XLSX shared strings/relationships and formula/date/merge cells, ODS repetitions/merges/precision, and an MS-CFB BIFF8 workbook independently identified by macOS `file` as `CDFV2 Microsoft Excel`. Native focused tests assert both outputs and production manager routing. Negatives cover traversal, absolute/reserved/colliding paths, links, expansion, ZIP64/encryption, external XLSX links/entities, encrypted/repetition-limit ODS, CFB chain loops, BIFF4, and XLS encryption. P08 added a genuine CFB/BIFF8 fixture whose first worksheet lacks EOF; the reader rejects it before the next sheet's records can be consumed. This is representative variant coverage; the final source-bound matrix and signed IDE interaction are separately recorded in the completion evidence.
